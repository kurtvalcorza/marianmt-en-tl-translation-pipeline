## Conformance notes

_Requirement identifiers in these notes (for example `ST1`, `PAR3`, `DAT24`, `EVAL21`) are the NOTEBOOK_SPEC 1.1 numbering they were written against; NOTEBOOK_SPEC 2.0 renumbered its sections and the pull request that migrated this repository reports conformance against the 2.0 pre-flight checklist (§26) and report format (§30)._

- **Standalone carrier (ST1–ST6):** the primary path performs no clone, repository install, or repository import. Section 2 is `src/marianmt_translation_pipeline/pipeline.py` verbatim (tagged `metadata.dimer.embedded_module`; the only rewrite makes the default weights directory working-directory-relative), Section 3 carries the model identity and the 8-file SHA-256 manifest inline and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins. `metadata.dimer.generated_from` records the repository, the revision generated from, the module's SHA-256, and the generator version.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried module, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Pickle trust boundary (MOD12):** the only upstream weight file is `pytorch_model.bin`; the opening cell says so in bold, Section 3's generated text states that `verify_snapshot` re-hashes every file and raises on a mismatch before `from_pretrained` runs, and the carried module's docstring and loader (`use_safetensors=False`, `weights_only=True`) are the code that enforces it. The export records `weight_format` and the pickle's manifest SHA-256.
- **Role stages:** `validate_inputs` (DAT24) writes `outputs/marianmt_translation_input_manifest.json` with the schema, ceilings, direction, each input's character and word counts, the settings in force, the verdict and one recorded rejection finding (an out-of-range `num_beams`); `evaluation_report` (EVAL21) writes `outputs/marianmt_translation_evaluation_report.json`, whose verdict is always `not-measurable` because the repository ships no metric helper — the report names the reference translations and caller-side BLEU/chrF scorer that would make the task measurable (EVAL9), and says so even when references are passed, because a handful of references is not a dispersion.
- The notebook exercises `MarianMTTranslationPipeline` carried verbatim in the notebook rather than reimplementing model loading; model acquisition goes through the package: `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh clone lacks (the git-ignored `pytorch_model.bin`), at the pinned revision, `verify_snapshot` re-hashes every entry, and `from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files (`local_files_only=True`, `trust_remote_code=False`); no cell outside the carried module calls `huggingface_hub` or `transformers`.
- The default sample is synthetic: the three English sentences the card-pass smoke translated, authored in code. The sample has no reference translations, so no BLEU/chrF is computed and none is manufactured; the sanity checks are plumbing checks only (one output per input in order, counts within ceilings, direction echoed).
- Decision rule and score semantics: beam search with 4 beams (`generation_config.json`) stated as the default, greedy as the alternative; the pipeline emits no probability or confidence and ships no acceptance threshold — the caller owns it. `stopped_by == 'max_new_tokens'` is explained as a truncated output.
- Ceilings `MAX_BATCH` (16), `MAX_TEXT_CHARS` (4000), `MAX_INPUT_TOKENS` (512, rejected not truncated), `MAX_NEW_TOKENS` (512), `MAX_NUM_BEAMS` (8), `DEFAULT_MAX_NEW_TOKENS` (128), `DEFAULT_NUM_BEAMS` (4), `DECISION_RULE` and the direction are printed before the model runs; the reverse direction, document-level translation, sampling, terminology control and `sacremoses` normalisation are named as out of scope.
- CPU is documented as adequate with the card-measured smoke numbers (6.0 s load + verify, 0.179 s / 0.108 s per 3-sentence batch on an Intel Core Ultra 9 275HX).
- `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog.
- `sacremoses` is not pinned and not installed: the notebook's opening **Environment note** says the tokenizer prints one `Recommended: pip install sacremoses.` warning and uses the identity normaliser, matching the card-pass smoke.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the
  clean-runtime execution requirement; a release review must confirm that a recorded clean run in
  `docs/release-verification.md` matches the notebook revision under review before the status is
  promoted to `Release-grade`.
