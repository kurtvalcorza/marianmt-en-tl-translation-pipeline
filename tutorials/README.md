## Curriculum unit

**English–Tagalog Translation — Preserving Meaning Across Languages** · Level 2 — Applied tasks · self-paced, `GUIDED`.

**Driving question:** *A translation sounds fluent — but did it preserve the meaning?*

**Learners:** basic Python and Colab familiarity; no prior machine-learning experience. Reading Tagalog helps in two
activities but is not required; the notebook shows learners how to record uncertainty instead of guessing.

**Learning outcomes.** By completing the notebook, learners can:

1. explain the task as *English text → translation model → Tagalog text* (one direction only);
2. distinguish pretrained inference, adaptation and evaluation;
3. compare a copy-source baseline, the pretrained model and the adapted model on the same held-out sentences;
4. interpret chrF and BLEU alongside their own reading of the translations;
5. conduct one controlled experiment and explain its limitations;
6. identify the evidence still needed before using translations in practice.

**Flow.** Orient (Start here, Input → Model → Output, roadmap) → Infrastructure (Sections 1–3, collapsed) →
4 Inspect data (references are one acceptable translation) → 5 Predict (negation, names, numbers, ambiguity,
terminology) → 6 Run the pretrained model (English / reference / output side by side, first rows in split order) →
7 Baseline and scores (chrF and BLEU explained; not "percent correct") → 8 Adapt (which parameters train, why the
budget is bounded, validation-based selection) → 9 Evaluate (three systems on the same 300 sentences, denominators,
changed / improved / worsened counts kept) → 10 Interpret (meaning checklist, surface flags calibrated on the human
references, the three largest sentence-level drops and gains by a fixed rule) → 11 Controlled activity (seven
instructional minimal pairs; checkpoint and decoding fixed; automatic cues, no quality score; optional
learner-authored pair) → 12 Export and reload (fidelity, not quality) → 13 Conclude (evidence-based conclusion
drafted from the run's numbers, with the learner's own observations in brackets). Five interpretation checkpoints
carry collapsible sample answers. The closing adds limitations, the evidence needed before practical use, optional
experiments, BYOD steps, troubleshooting, a glossary, references and the AI Assistance Disclosure.

**Controlled activity data.** The seven probe pairs (negation ×3, number ×2, person name, place name) are
instructional probes written for this notebook: not Tatoeba data, checked at run time to appear in no split and nowhere
in the corpus, without reference translations and without bilingual review. The notebook therefore reports no quality
score for them, only string cues (negator present/absent, digit present, name present) and the list of other words
that changed; learners record their own judgement as *yes / no / uncertain* in `outputs/marianmt_translation_probes.csv`.
Completion records are optional; the notebook requires no submission.

The validator checks the markers, the checkpoint/sample-answer pairing, and that `BYOD_PATH`, `MY_ORIGINAL` and `MY_CHANGED` default to empty.
- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 3 modules verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports), Section 3 carries the 8-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Pickle trust boundary (MOD12):** the only upstream weight file is `pytorch_model.bin`; the opening cell says so in bold, Section 3's generated text states that `verify_snapshot` re-hashes every file and raises on a mismatch before `from_pretrained` runs, and the carried module's loader (`use_safetensors=False`, `weights_only=True`) is the code that enforces it. The export records `weight_format` and the pickle's manifest SHA-256, and the adapter manifest records the same digest as its base.
- **Model acquisition (MOD1–MOD9):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh clone lacks, at the pinned revision; `verify_snapshot` re-hashes every entry; `MarianMTTranslationPipeline.from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files (`local_files_only=True`, `trust_remote_code=False`); no cell outside the carried modules calls `huggingface_hub`, `transformers`, `safetensors` or `urllib`.
- **Data (DAT1–DAT9, ST6):** the default sample is one pinned object — `en-tl.txt.zip` (312,459 bytes, SHA-256 `9abddc7d…`) from OPUS at `object.pouta.csc.fi` — refused on any mismatch before it is read, read member by member with no `extractall`, filtered and de-duplicated case-insensitively on the English side, and cut by a seeded shuffle into 1,200 / 200 / 300 disjoint records (`check_split_disjoint` asserts it). The template adds a second *External access* bullet naming the host, the byte count and the CC BY 2.0 FR licence.
- **Stages (§4.1):** `fetch_corpus` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition) → `validate_dataset` + `check_split_disjoint` + refusal probes (validation, with three digests) → `validate_inputs` + `pipe.translate` with sanity checks (inference contract) → `copy_source_baseline` + `pipe.evaluate` on the frozen model (baselines) → `pipe.adapt` (bounded fine-tuning) → `pipe.evaluate` on validation and test with the comparison (evaluation) → surface flags and the probe activity (interpretation) → `pipe.translate` on unseen sentences + `evaluation_report` with references (inference) → `pipe.save_artifact` → `MarianMTTranslationPipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** the pipeline emits no probability, confidence or score; chrF and BLEU are corpus-level agreement with references (own implementations, sacrebleu-style, not sacrebleu-identical), explained as overlap scores that are not "percent correct" and that mark down valid paraphrases; no acceptance threshold ships, and `stopped_by == 'max_new_tokens'` is explained as a truncated output. Sentence-level chrF is shown only to find sentences worth reading. The surface flags are labelled as heuristics and run on the human references as a false-alarm check; the probes carry no quality score.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11/EVAL15):** the copy-source baseline and the pretrained model are scored on the same 300 test sentences as the adapted model, the frozen BLEU is read against the upstream README's Tatoeba figure as a sanity check, every metric is labelled as one seeded split of one corpus with no dispersion estimate, and corpus scores are paired with sentence-level outputs chosen by documented rules (first rows in split order; the three largest drops and gains).
- **Split integrity (SPL1–SPL8):** the split is seeded and source-disjoint; validation selects the epoch and the test split is used for nothing but the final evaluation; the notebook states that near-duplicate pairs from one document or session must be split by that grouping. The instructional probes are asserted to be outside every split and the corpus.
- **Ceilings (VAL6):** `MAX_BATCH` (16), `MAX_TEXT_CHARS` (4,000), `MAX_INPUT_TOKENS` (512, rejected not truncated), `MAX_NEW_TOKENS` (512), `MAX_NUM_BEAMS` (8), the record bounds (8..20,000), the id pattern and the training-only 128-piece truncation are stated in the Prerequisites and printed before the model runs; four dataset refusals and one settings refusal are demonstrated.
- **BYOD (DAT10–DAT19, EXE2):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, user pairs are read from `BYOD_PATH` if set (no `google.colab` import) or from an upload, and flow through the same validation, split, baselines, fine-tuning, evaluation, meaning checks, probes, inference, export and reload cells. The expected schema and the privacy guidance — a proprietary translation memory is restricted data — are stated in the Prerequisites and in Section 4, and the training split is written to `outputs/marianmt_translation_train.csv` in that shape.
- `sacremoses` is not pinned and not installed: the notebook's opening **Environment note** says the tokenizer prints one `Recommended: pip install sacremoses.` warning and uses the identity normaliser; every recorded number was produced in that state.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
