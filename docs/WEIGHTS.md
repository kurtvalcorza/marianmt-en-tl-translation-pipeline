# Weight provenance and DIMER hosting

- Upstream: `Helsinki-NLP/opus-mt-en-tl`
- Immutable revision: `e46e1761492cb6a6fb9515a72bb55ca654815ca5`
- Weight format: **PyTorch pickle** (`pytorch_model.bin`, 296,434,867 bytes, float32) — the only weight file upstream at this revision; there is no `model.safetensors`. SHA-256 `e418d573a717b2c81eaa3a80c8eb68f203c14c6b734dd36d41708c1369d0eb44`, recorded in the manifest and re-computed before every load.
- Upstream weight license: Apache-2.0 (`license: apache-2.0` in the pinned upstream README front matter). Trained by the Helsinki-NLP group (OPUS-MT, Tiedemann & Thottingal 2020) on the `opus+bt` dataset with the `transformer-align` architecture; original Marian weights at `opus+bt-2020-02-26.zip` (pinned README).
- Local layout: `weights/opus-mt-en-tl/` holds the 8 files listed in `dimer-base-manifest.json` (`config.json`, `generation_config.json`, `pytorch_model.bin`, `source.spm`, `target.spm`, `tokenizer_config.json`, `vocab.json`, upstream `README.md`; `totalBytes` 299,423,522) with byte size and SHA-256 for each. `verify_snapshot()` in `src/marianmt_translation_pipeline/pipeline.py` checks all of them before any load; `stage_missing_files(allow_download=True)` fetches only absent entries at the pinned revision into that directory. `.bin` files are git-ignored; the Git repository does not vendor the checkpoint.
- DIMER hosting: Apache-2.0 permits use, modification, redistribution and commercial use subject to preservation of the license and notices. DIMER may mirror the pinned checkpoint in its model store under those terms; the mirror must carry the same SHA-256 so the pipeline's digest check keeps holding.
- Loader trust boundary (pickle checkpoint): `verify_snapshot` re-hashes `pytorch_model.bin` against the manifest **before** `torch` or `transformers` is imported, so a modified pickle never reaches a deserialiser; then `MarianMTModel.from_pretrained(<verified dir>, use_safetensors=False, weights_only=True, trust_remote_code=False, local_files_only=True)` makes `transformers` call `torch.load(..., weights_only=True)`, whose restricted unpickler admits tensors, primitives and containers only. The card-pass smoke wrapped `torch.load` and observed exactly two calls on `pytorch_model.bin`, both with `weights_only=True` (`map_location='meta'` for the key scan, then `'cpu'`). The Hub is consulted only when `allow_download=True` is passed explicitly, and then only at the pinned revision.
