#### Description

`Helsinki-NLP/opus-mt-en-tl` is an OPUS-MT machine-translation model for English→Tagalog released by the Helsinki-NLP group on 2020-02-26 (pinned README: `opus+bt-2020-02-26.zip`) and converted to the `MarianMTModel` class of `transformers`, pinned here to revision `e46e1761492cb6a6fb9515a72bb55ca654815ca5`. Read from the snapshot `config.json`, it is a small encoder-decoder Transformer of the `transformer-align` type trained with Marian NMT (Junczys-Dowmunt et al., 2018): 6 encoder and 6 decoder layers, `d_model` 512, 8 attention heads, feed-forward width 2048, swish activations, static sinusoidal position embeddings, and one 57,373-entry SentencePiece vocabulary shared by encoder and decoder (`source.spm`/`target.spm`, `vocab.json`); roughly 77 M parameters in a 296 MB float32 checkpoint. At inference the encoder reads the source sentence once and the decoder emits one SentencePiece token per step from the pad/start token (57372) until `</s>` (id 0) or a step ceiling, under beam search with 4 beams by default (`generation_config.json`); nothing is adapted, fine-tuned or conditioned beyond the text the caller supplies, and the direction is English→Tagalog only. What this repository adds is packaging and a bounded adaptation contract: the `MarianMTTranslationPipeline` class in `src/marianmt_translation_pipeline/pipeline.py`, digest verification of the local snapshot (`verify_snapshot`, `stage_missing_files`) — which here guards a **pickle** weight file, since upstream ships no SafeTensors — input validation with named ceilings, batched translation with a fixed output contract, the `validate_inputs` and `evaluation_report` stage helpers, reference-based corpus metrics (`metrics.py`: chrF and BLEU, own implementations) with a copy-source baseline, a digest-pinned real parallel corpus (`samples.py`: Tatoeba en–tl via OPUS, validated and split without source leakage), supervised fine-tuning of the last *k* decoder blocks (`adapt`, default 2 of 6) with validation-chrF epoch selection, and a safetensors adapter (`save_artifact` / `from_artifact`) that carries only the trained tensors and is bound to the base weight digest.

#### Intended Use and Limitations

###### Primary Intended Uses

The task is sentence-level machine translation: input a batch of 1–16 English strings, output one Tagalog string per input, in order, with the encoder and decoder token counts and the stop reason. Envisioned applications are draft translation of short English sentences and passages into Tagalog — user-interface strings, notices, survey items, teaching examples — in research prototypes, language-technology teaching material, and as a fixed, offline, CPU-capable baseline against which larger multilingual models or commercial translation APIs are compared on Philippine-language content. The second intended use is bounded domain adaptation: given 8–20,000 `{id, source, target}` sentence pairs from the operator's own domain, `adapt` fine-tunes the last two decoder blocks (8,408,064 parameters, about 11 % of the model) for a few epochs on CPU, selects the epoch by validation chrF, and `save_artifact` exports the trained tensors as a 33.6 MB safetensors adapter that `from_artifact` applies on top of the digest-verified base — the recorded run lifts held-out Tatoeba chrF from 56.46 to 59.36 and BLEU from 27.13 to 33.75 in 56 s of training. In a larger system the pipeline is an inference component that produces candidate Tagalog text for a human reviewer or a downstream scorer; it is chosen where a 296 MB float32 checkpoint, no network dependency at inference, and the CPU latency measured in §Environment (about 0.03–0.06 s per sentence in a batch of three) are acceptable and where the caller can supply references for the quality check the repository's `evaluate` and `evaluation_report` helpers perform. Only the en→tl direction is provided; Tagalog→English is a different OPUS-MT checkpoint this repository does not package.

###### Primary Intended Users

The intended users are machine-learning engineers, NLP researchers, localisation engineers and application developers integrating an offline English→Tagalog baseline into research prototypes, internal tooling, or the DIMER model workbench, and adapting it to a domain for which they hold a small referenced parallel corpus. The pipeline assumes its users understand that beam search returns one deterministic candidate rather than a probability over translations, that a translation can be fluent and wrong (dropped negations, wrong pronouns, untranslated named entities, code-switched English left in place), that the model reads at most 512 SentencePiece tokens of input and works best on single sentences, that the source-side Moses punctuation normalisation is skipped in this configuration (see §Instrumentation), that corpus chrF and BLEU measure agreement with references rather than adequacy and are only comparable across runs scored on the same references with the same implementation, and that a fine-tuned adapter is only as good as the split discipline behind it — near-duplicate pairs from one document or session must be grouped before splitting or the validation score is inflated. It is not designed for hobbyist chat, for translating documents wholesale without segmentation, or for any Tagalog→English use.

###### Out-of-scope use cases

1. **Capability boundary:** not bidirectional — Tagalog or any other source language produces garbage, not a translation (`source_lang: en`, `target_lang: tl` in the pinned `tokenizer_config.json`); not a document translator (no sentence splitting, no cross-sentence context, no glossary or terminology control); not an instruction-following or chat model; not a classifier or embedder (for those use `bert-masked-lm-pipeline`); for English-source translation into German/French/Romanian use `t5-base-text2text-pipeline`. Not a general training framework: `adapt` fine-tunes only whole decoder blocks (1–6 of them, the last *k*), with AdamW, a fixed learning rate, no scheduler, no mixed precision, no gradient accumulation and no early stopping beyond epoch selection; the encoder, the embeddings and the vocabulary are never modified, so it cannot teach the model new source-side vocabulary, a new language pair or a new direction.
2. **Input boundary:** only a sequence of `str` is accepted (`TypeError` for a bare string or a non-`str` item); an empty batch or more than `MAX_BATCH = 16` items, an empty or whitespace-only item, an item over `MAX_TEXT_CHARS = 4000` characters, or an item that tokenises to more than `MAX_INPUT_TOKENS = 512` pieces including `</s>` is rejected with `ValueError` — the pipeline refuses rather than silently truncating; `max_new_tokens` is capped at `MAX_NEW_TOKENS = 512` and `num_beams` at `MAX_NUM_BEAMS = 8`. Datasets for `validate_dataset`, `evaluate` and `adapt` are lists of `{id, source, target}` records: fewer than `MIN_RECORDS = 8` or more than `MAX_RECORDS = 20000` records, a duplicate or malformed `id` (pattern `^[A-Za-z0-9_.:-]{1,64}$`), an empty `source` or `target`, a field over `MAX_TEXT_CHARS`, or a record that is not a mapping is rejected with `ValueError`; `evaluate` accepts 1–`MAX_EVAL_RECORDS = 2000` records and refuses a `batch_size` outside 1..16; `adapt` requires at least `MIN_RECORDS` training records and refuses `epochs` outside 1..20, `batch_size` outside 1..64, `lr` outside (0, 1e-2] or `trainable_decoder_layers` outside 1..6. Training pairs are truncated to `MAX_TRAIN_TOKENS = 128` pieces on each side (the only truncation in the repository, and it applies to training only). `load_artifact` refuses an adapter whose `format`, `base_model` id, revision or `weight_sha256` differ from the constants, whose tensor names are not `model.decoder.layers.*`, or whose file digest differs from its manifest.
3. **Decision boundary:** not for translations that are acted on without a bilingual human reading them — medical instructions, legal notices, safety warnings, financial or government communications to Tagalog speakers, content published under a person's name — and not for any use where a mistranslated sentence causes harm before it is checked. A chrF or BLEU gain on the operator's validation split is not a release decision: it is a single seeded split of one corpus with no dispersion estimate, and an adapter that helps on Tatoeba-style short sentences can degrade other registers the corpus never contained.

#### Factors

###### Groups

The pipeline is human-adjacent rather than human-centric: it translates natural-language text that routinely mentions and addresses people, but it carries no demographic labels and its outputs are strings, not decisions about a person. The pinned upstream README reports no group-level breakdown and carries no bias statement; the training data is described only as `opus+bt` — parallel corpora collected in OPUS plus back-translated monolingual text — whose composition by domain, register, dialect, or the demographics of the speakers and translators the upstream authors did not audit. Neither the upstream card nor this repository reports how translation quality varies with the source register (formal vs. colloquial English), with Philippine vs. non-Philippine named entities, with gendered or honorific forms (Tagalog pronouns are gender-neutral while its politeness markers such as *po* are not, so the model chooses a register the English source never specified), or between standard Tagalog and other Philippine languages the OPUS data may have mixed in under the `tl` code. The fairness audit therefore transfers to the operator: before deployment, score outputs on a referenced sample of your own sentences stratified by the groups and registers that matter to your application, and treat systematic register defaulting or degraded quality on a group as a blocker.

###### Instrumentation

There is no physical sensor: the training data was produced by software and people. OPUS parallel corpora are aligned sentence pairs harvested from published bilingual sources (subtitles, software localisation files, religious and government texts, web crawls — the OPUS collection, Tiedemann 2012), and the `bt` half is English text machine-back-translated from Tagalog monolingual data by an earlier model, so part of the training signal is itself machine output. Upstream pre-processing was "normalization + SentencePiece" (pinned README). The instrument characteristics that reach the model are text normalisation and tokenisation: in this repository's configuration `MarianTokenizer` finds no `sacremoses` package (`transformers/models/marian/tokenization_marian.py`, lines 169–176) and uses the identity function as the source-side punctuation normaliser, so curly quotes, non-breaking spaces, Unicode dashes and full-width punctuation in the caller's input reach SentencePiece unnormalised and can shift the output; the smoke run recorded the one-line `Recommended: pip install sacremoses.` warning and ran in that state. Characters outside the SentencePiece vocabulary become `<unk>` and vanish or garble the output. The pipeline does not detect encoding damage, sentence boundaries, code-switching or a change in domain; it only rejects the type, batch, length and token-count violations listed above.

###### Environment

Operating environment: Python 3.12 with `torch==2.14.0`, `torchvision==0.29.0`, `torchaudio==2.11.0`, `transformers==4.57.6`, `tokenizers==0.22.2`, `sentencepiece==0.2.2` (exact pins in `pyproject.toml`; `sacremoses` is not pinned and not installed); `from_pretrained` picks `cuda:0` when available, else CPU, and loads the weights in float32 on both. Security of the load path: the only weight file is `pytorch_model.bin`, a PyTorch pickle; `verify_snapshot` re-hashes it against the manifest SHA-256 before `torch` or `transformers` is imported, and the loader passes `use_safetensors=False` and `weights_only=True`, which `transformers` 4.57.6 turns into `torch.load(..., weights_only=True)` (`modeling_utils.py`, `load_state_dict`) — a restricted unpickler that admits tensors, primitives and containers only. The smoke run wrapped `torch.load` and observed exactly two calls on `pytorch_model.bin`, both with `weights_only=True` (`map_location='meta'` for the key scan, then `'cpu'`). Measured on this repository's smoke run (Windows venv `dimer-next16`, `CUDA_VISIBLE_DEVICES=-1`, `device="cpu"` passed explicitly, Intel Core Ultra 9 275HX): loading and digest-verifying the 299 MB snapshot took 6.0 s; a batch of three sentences (`The house is wonderful.`, `Good morning to all of you.`, `Where is the nearest hospital?`; 6/8/7 input tokens) translated in 0.179 s with 4 beams and 0.108 s greedy, producing `Ang bahay ay kahanga - hanga.`, `Magandang umaga sa inyong lahat.` and `Nasaan ang pinakamalapit na ospital?` (7/7/6 generated tokens, all stopped by `</s>`; greedy and beam-4 identical on these inputs). Adaptation on the same machine, from the committed notebook's recorded run: fetching and reading the pinned 312,459-byte Tatoeba zip and cutting 7,741 filtered unique pairs into 1,200 / 200 / 300 records took under 0.1 s from the cache; scoring the frozen model on the 300-pair test split with 4 beams took 11.2 s (chrF 56.46, BLEU 27.13, copy-source baseline chrF 11.28); two epochs of AdamW over 1,200 pairs at batch 16 with the last two decoder blocks trainable (8,408,064 of 74,037,760 parameters, `lr=1e-4`, weight decay 0.01, gradient clipping 1.0, labels padded with −100, seed 0) took 56.2 s including the per-epoch validation scoring (validation chrF 58.54 frozen → 60.32 → 61.50; epoch 2 selected); re-scoring the test split took 10.7 s (chrF 59.36, BLEU 33.75); the adapter is 33,638,224 bytes over 52 tensors, and the reloaded pipeline reproduced 8/8 translations byte for byte. Two counter-examples recorded during the build on the same split: training all six decoder blocks (25.5 M parameters) reached chrF 59.59 / BLEU 33.66 in 90 s and the full model (74 M) chrF 59.19 / BLEU 33.23 in 124 s — no gain over the default two blocks. CUDA and the Hub-download path were not executed. Data environment: inputs are assumed to be single, well-formed English sentences of the kind found in the OPUS sources (subtitles, localisation strings, general prose); multi-sentence inputs are translated as one sequence with no boundary handling, inputs above 512 tokens are refused, and text far from that distribution (code, tables, heavy slang, other languages) yields output the pipeline cannot flag as degraded.

#### Metrics

###### Performance Measures

Two corpus-level agreement measures, both implemented in `src/marianmt_translation_pipeline/metrics.py` with no external scorer: **chrF** (character n-gram F-score, orders 1–6, β = 2, whitespace removed, precision and recall averaged over orders, sacrebleu-style but not sacrebleu-identical) and **BLEU-4** (regex word tokens, modified n-gram precision with brevity penalty, single reference, corpus-level). `translation_metrics(hypotheses, references)` returns both with the counts they were computed over; `pipe.evaluate(records)` translates a validated dataset and returns them with `hit_token_ceiling`, the generation settings, the model identity and the elapsed time; `copy_source_baseline(records)` scores the English input as if it were the Tagalog output, the floor any translation must clear. chrF is the primary measure because it is tolerant of Tagalog affixation and orthographic variants that word-level BLEU punishes, and it selects the epoch in `adapt`; BLEU is reported alongside because upstream reports it (26.6 on `Tatoeba.en.tl`; the frozen model scores 27.13 on this repository's seeded 300-pair test split, a sanity match, not a reproduction — different release, different split, different scorer). Each `translations` entry still carries only descriptive fields (`text`, `input_tokens`, `generated_tokens`, `stopped_by` with `eos` or `max_new_tokens`), and neither metric can be computed for an arbitrary input: the public `evaluation_report(result, references)` helper scores the supplied references and returns `measured` (≥ `MIN_SCORED_REFERENCES = 50` items) or `measured-small-sample` (fewer, naming the missing dispersion), raises if the reference count does not match, and without references still returns `not-measurable` with an empty `metrics` list and a `needs` field naming the references that would be required. Recorded values on the seeded Tatoeba test split (300 pairs, 4 beams, 128 new tokens): copy-source chrF 11.28 / BLEU 0.0; frozen chrF 56.46 / BLEU 27.13; adapted (last two decoder blocks, two epochs) chrF 59.36 / BLEU 33.75; six unseen sentences after adaptation chrF 62.66 / BLEU 19.58 with a `measured-small-sample` verdict.

###### Decision thresholds

The default decision rule is beam search with `num_beams = 4`, taken from the snapshot `generation_config.json` and exposed as `DEFAULT_NUM_BEAMS` and `DECISION_RULE` (reported back in `generation.decision_rule`): at each step the four highest-scoring partial sequences are kept and the highest-scoring complete sequence is returned. With `num_beams = 1` this collapses to greedy decoding, an implicit per-step argmax; in neither mode is there a minimum-probability cut-off, so the model always produces some token. Generation stops at `</s>` or at `max_new_tokens` (default `DEFAULT_MAX_NEW_TOKENS = 128`, ceiling 512); the snapshot's `bad_words_ids` (the pad token) and `forced_eos_token_id` apply as `model.generate` reads them from `generation_config.json`. No acceptance threshold on output quality is shipped because the model emits no confidence: the trade-off the operator sets is between search effort and latency (`num_beams`, roughly 1.7× slower at 4 beams than greedy in the smoke) and between truncated and over-long output (`max_new_tokens`), judged on their own references. The one selection rule in the adaptation path is explicit: `adapt` keeps the epoch with the highest validation chrF (epoch 0 is the frozen model, so a run that never improves returns the base weights unchanged) and reports `best_epoch` and the per-epoch history; whether the resulting gain on the test split is worth deploying is the operator's decision and no threshold is shipped for it.

###### Approaches to uncertainty and variability

Every reported metric is one value on one seeded split of one corpus: `build_sample_dataset(seed=42)` fixes the 1,200 / 200 / 300 partition of the 7,741 filtered Tatoeba pairs, `adapt(seed=0)` fixes the shuffle order and initial state, and no repetition over seeds or splits is performed, so no confidence interval or standard deviation is available and none is claimed — the +2.90 chrF / +6.62 BLEU gain on the test split is a point estimate whose spread is unknown, and the six-sentence `measured-small-sample` verdict says so explicitly. The upstream Tatoeba BLEU/chr-F figures are likewise single evaluations by the upstream authors with no reported interval. Inference is deterministic for a given input batch, settings, weights, device and library versions: sampling is disabled (`do_sample=False`), dropout is off under `model.eval()`, and no seed is needed — the smoke run produced identical strings under greedy and 4-beam decoding for its three sentences, and the reloaded adapter reproduced 8/8 translations. Training is deterministic on one CPU for one seed and library set but is not bit-reproducible across devices or `torch` builds. Batch composition can still matter at inference: inputs are padded to the longest item, and float32 kernel differences between CPU and GPU, or between padded and unpadded runs, can flip a near-tied token and change the rest of the sequence from that point on. The pipeline emits no probability or confidence at all: `generated_tokens` and `stopped_by` are counts and flags, not scores. A caller who needs a calibrated confidence in a translation must compute it themselves (for example, sequence log-probabilities via `transformers` `output_scores`, or a quality-estimation model, followed by a calibration map fit on their own judged data); nothing in this repository does so.

#### Ethical considerations and biases

###### Data

Upstream discloses that the model was trained on `opus+bt` — OPUS parallel data for en–tl plus back-translated text — with the original weights, test translations and scores linked from the pinned README; disclosure stops there — no list of the OPUS sub-corpora used, no per-corpus licensing, consent or personal-data audit is given, and OPUS sources such as subtitles, localisation files and web crawls are known to contain names and other personal data of identifiable people, so the presence of personal data is not ruled out and should be assumed. This repository distributes code, tests and documentation; the 296 MB `pytorch_model.bin` and the tokenizer files are git-ignored and staged locally under `weights/opus-mt-en-tl/` with a manifest. The adaptation sample is not shipped either: `fetch_corpus` downloads one pinned object at run time — the Tatoeba en–tl Moses release `v2023-04-12` from OPUS (`object.pouta.csc.fi`, 312,459 bytes, SHA-256 `9abddc7d…`), 8,785 crowd-sourced sentence pairs under CC BY 2.0 FR (Tatoeba contributors; OPUS redistribution) — refuses any other bytes, and caches it under `weights/tatoeba-en-tl/` (git-ignored). Tatoeba sentences are written and translated by volunteers and can name real people, places and opinions; the sample is used only to fit and score the last two decoder blocks, and the filtered 7,741-pair subset is reproducible from the digest and `SAMPLE_SEED = 42`. Nothing in this corpus is a substitute for the operator's own domain: BYOD records pass through the same validation and are written to `outputs/…_train.csv` in the notebook, so a proprietary translation memory is restricted data the moment it is loaded. The operator must audit the text they submit or train on for personal, confidential or proprietary content; the pipeline performs no such check and keeps no log.

###### Human Life

The pipeline is not intended for decisions in health, safety, criminal justice, employment, credit, housing or any other domain central to human life, and it has not been validated or certified for any of them by anyone. Its only validation is the offline unit suite (35 tests, plus 2 model-backed tests that run when the snapshot is staged) and the CPU runs recorded in this repository on Tatoeba sentences. Where a sensitive use is foreseeable — translating a medication leaflet, an eviction notice, a disaster warning or a consent form into Tagalog, or fine-tuning on such material — it is admissible only with a bilingual human reading the output against the source before it is used, an independent evaluation with references on representative documents, and whatever regulatory clearance the domain requires; a machine translation from this pipeline must never be the record of what an English source said.

###### Mitigations

Implemented and inspectable in `src/marianmt_translation_pipeline/pipeline.py`: (1) supply chain — `MODEL_REVISION` is a 40-hex commit; `stage_missing_files` refuses a manifest whose `modelId`/`revision` differ from the constants and fetches absent files only with `allow_download=True`, one file at a time at that revision; `verify_snapshot` re-hashes every file in `weights/opus-mt-en-tl/dimer-base-manifest.json` — including the 296 MB pickle — and raises on the first size or SHA-256 mismatch before `torch` or `transformers` is imported (`tests/test_import_boundary.py`); loading is `local_files_only=True` from the verified directory, or from the Hub with `revision=MODEL_REVISION` only when explicitly allowed; `MarianMTModel.from_pretrained` is called with `use_safetensors=False` (naming the pickle) and `weights_only=True`, so deserialisation goes through `torch.load(weights_only=True)`, as the smoke observed; `trust_remote_code=False` always. (2) Input integrity — `_validate` rejects a non-sequence, an empty or oversized batch (`MAX_BATCH`), non-`str`, empty or over-length (`MAX_TEXT_CHARS`) items, over-token items (`MAX_INPUT_TOKENS`, counted with the real tokenizer) and out-of-range `max_new_tokens`/`num_beams` before the model runs. The public `validate_inputs()` helper applies the same checks through the same private `_check_inputs()` function and returns an input manifest (schema, ceilings, per-input observations, verdict, findings), so a caller can record exactly what was accepted or rejected without duplicating the validation logic; the token ceiling stays inside the pipeline because it needs the loaded tokenizer. (3) Reproducibility — exact `==` dependency pins, `model.eval()`, float32, deterministic decoding, and `model_id`/`model_revision`/`generation` in every result. (4) Refusals — no sampling, no reverse direction, no sentence splitting; a missing snapshot with `allow_download=False` raises `FileNotFoundError`. (5) Dataset integrity — `fetch_corpus` verifies the byte count and SHA-256 of the pinned Tatoeba zip before it is read and reads its two members with `ZipFile.read` (never `extractall`); `validate_dataset` enforces the record schema, the id pattern, the size bounds and the character ceilings and returns a content digest; `check_split_disjoint` fails on any source shared between splits; `split_dataset` is seeded. (6) Training and artifact integrity — `adapt` trains only whole decoder blocks under an explicit `trainable_decoder_layers` bound, restores the best-epoch weights so a failed run leaves the base model, and truncates training pairs at 128 pieces on each side (the only truncation, training only); `save_artifact` writes a safetensors file of the trained tensors plus a manifest carrying the format tag, the base model id, revision and pickle digest, the tensor list and the file SHA-256; `load_artifact` refuses any mismatch in those fields, any tensor outside `model.decoder.layers.*`, and any digest drift, so an adapter cannot be applied to a different base or altered in transit without failing. No statistical mitigation (re-balancing, output filtering) is applied because the pipeline ships no content filter and adapts to whatever pairs the operator validates.

###### Risks and harms

Mistranslation: the decoder produces fluent Tagalog whether or not it preserves the source meaning — a dropped *not*, a wrong number, an English idiom rendered literally — and the Tagalog reader who trusts it bears the harm; likelihood rises with sentence length, with domain distance from the OPUS sources, and with English slang or jargon. Register and pronoun choice: Tagalog politeness markers (*po/opo*) and plural-honorific pronouns are chosen by the model for a source that never specified them, which can read as rude or as inappropriately deferential to the addressee. Untranslated or hallucinated entities: names, acronyms and numbers can be copied, altered or dropped; a third party named in the text bears that harm when it is published. Supply chain: the upstream weight file is a pickle; the manifest digest and `weights_only=True` are the controls, and a mirror that serves a different file fails the digest check rather than loading. Automation bias: fluent output is checked less carefully than a rough one. Silent quality loss: multi-sentence inputs are translated as one sequence, inputs near 512 tokens are handled worse than short ones, and `max_new_tokens` truncation cuts mid-sentence. Adaptation drift: an adapter trained on a narrow corpus can shift register (Tatoeba is informal, first-person, short) and degrade sentences unlike the training pairs while the validation score rises; the artifact carries no record of what it was trained on beyond the caller's optional metadata, so a misapplied adapter is a supply-chain risk of the operator's own making — the base-digest binding stops it from loading on the wrong model, not on the wrong domain. Data exposure: submitted text is processed in memory only, but the operator's surrounding system may log it. Magnitude ranges from an awkward sentence to a materially false instruction delivered in the reader's language.

###### Use cases

## Input/output contract

- `MarianMTTranslationPipeline.from_pretrained(device=None, weights_dir=None, allow_download=False)`
- `translate(texts, *, max_new_tokens=128, num_beams=4)` — `texts`: 1–16 `str`, each non-empty, ≤ 4000 chars, ≤ 512 SentencePiece tokens incl. `</s>`; `max_new_tokens` 1–512; `num_beams` 1–8. Returns `{"translations": [{"source", "text", "input_tokens", "generated_tokens", "stopped_by"}, ...], "n", "direction": "en->tl", "generation": {"max_new_tokens", "num_beams", "do_sample", "decision_rule"}, "device", "source", "model_id", "model_revision"}`.
- `validate_inputs(texts, *, max_new_tokens=128, num_beams=4, names=None)` — input manifest; `evaluation_report(result, references=None, *, sample_kind="synthetic")` — `measured` (≥ 50 references) / `measured-small-sample` / `not-measurable` (no references) with `metrics` `[{name, value}]`; raises `ValueError` when the reference count differs from the result.
- `verify_snapshot(path=None)` — returns the manifest dict with `path`; raises `FileNotFoundError` / `ValueError`.
- `stage_missing_files(path=None, *, allow_download=False, downloader=None)` — returns the list of manifest entries fetched.
- `evaluate(records, *, batch_size=16, max_new_tokens=128, num_beams=4)` — validated `{id, source, target}` records (1–2,000) → `{n, chrf, bleu, hypothesis_chars, reference_chars, hit_token_ceiling, generation, adapted, seconds, model_id, model_revision}`.
- `adapt(train, val, *, epochs=2, lr=1e-4, batch_size=16, trainable_decoder_layers=2, seed=0, progress=None)` — requires `from_pretrained`; `train` 8–20,000 records, `val` optional (1–2,000; without it every epoch is kept); fine-tunes the last *k* decoder blocks (1–6; `epochs` 1–20, `batch_size` 1–64, `lr` (0, 1e-2]) with AdamW, keeps the epoch with the highest validation chrF; returns `{trainable_decoder_layers, n_trainable, n_total, epochs, best_epoch, selection, lr, batch_size, max_train_tokens, n_train, n_val, seed, seconds, history, trainable_names}`; sets `pipe.adapter`.
- `save_artifact(directory, metadata=None)` → directory with `adapter.safetensors` (trained tensors only) + `manifest.json` (`format` = `org.valcorza.marianmt-en-tl.adapter.v1`, base `model_id`/`model_revision`/`weight_sha256`, `tensors`, `sha256`); `load_artifact(directory)` verifies, applies the tensors in place and returns the manifest; `MarianMTTranslationPipeline.from_artifact(directory, *, device=None, weights_dir=None)` loads the verified base and applies it.
- `metrics.py`: `chrf(hyps, refs)`, `bleu(hyps, refs)`, `translation_metrics(hyps, refs)`, `copy_source_baseline(records)`. `samples.py`: `fetch_corpus(cache_dir=None, fetcher=None)`, `read_corpus_pairs(data)`, `filter_pairs`, `build_sample_dataset(pairs, seed=42, sizes=SAMPLE_SPLIT)`, `fetch_sample_dataset()`, `validate_dataset(records)`, `dataset_digest`, `check_split_disjoint(splits)`, `split_dataset(records, val_fraction=0.15, test_fraction=0.2, seed=0)`, `load_byod_dataset(path)` (CSV / JSON / JSONL), `write_dataset_csv(records, path)`.
